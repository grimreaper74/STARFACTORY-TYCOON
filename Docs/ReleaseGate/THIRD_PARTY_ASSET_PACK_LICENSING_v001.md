# Third-party asset packs — licensing position for a Steam release

Snapshot: **2026-08-16**. Companion to
[Asset provenance and promotion](ASSET_PROVENANCE_AND_PROMOTION.md). This
records what is owned and what must be verified. It is engineering guidance,
not legal advice, and it does not clear anything for release on its own.

## Position for a Steam release

Shipping Fab content inside a commercial game distributed on Steam is the
intended use. There is no Epic Store exclusivity and no obligation to ship on
Epic. The points that need action are below.

1. **Licence tier follows revenue.** Fab's standard licence separates Personal
   and Professional by annual gross revenue. Confirm the current threshold and
   the tier held for each paid pack in Fab before taking money for the game, and
   budget for an upgrade if Line Boss earns above it.
2. **Ship them, do not re-ship them as assets.** Cooked into a packaged build is
   fine. Redistribution as reusable assets, sublicensing and resale are not.
   This is a concrete reason not to publish an editor build or loose `.uasset`
   files.
3. **Licences are per user.** Solo development is covered. Anyone joining the
   project needs their own.
4. **The Epic and sponsored packs carry the lightest terms** — Automotive
   Materials, the Megascans sample and the MoCap permanent-collection pack.

## Steam-specific obligation

Steam requires AI-generated content to be disclosed at store submission. The
project already tracks Meshy generations under AI disclosure in
[Asset provenance and promotion](ASSET_PROVENANCE_AND_PROMOTION.md); that record
is what the submission answer should be built from. Fab itself now carries
`is_ai_generated` and `is_ai_forbidden` flags per listing, so provenance of
bought content is also worth capturing at import time.

## Consequences for the OneFactory contracts

Pack content is external-generated by the presentation contract's definition,
and the Body/Weld presentation currently fails closed on anything outside:

- `/Game/LineBoss/Candidates/WeldShop/BodyShopRobotNative_v001/`
- `/Game/LineBoss/Candidates/WeldShop/BodyShopSupportKitNative_v002/`

Adopting pack meshes therefore requires a versioned `v002` presentation with an
extended allowlist and regenerated instance counts, not an edit in place. The
frozen counts — 469 for Body/Weld — are asserted by tests and must be
regenerated deliberately.

## Sequence before any pack asset is imported

1. Put `Content/` under Git LFS. It is currently unversioned, and 8.7 GB of pack
   assets without version control removes the ability to roll back.
2. Record each pack's Fab listing, licence tier and acquisition date in the
   provenance authority at import time, not afterwards.
3. Import into a new namespace rather than an existing candidate root, so
   provenance stays separable from the native procedural families.
4. Extend the presentation allowlist as a versioned `v002` with regenerated
   counts and updated tests.

## Verify before release

- The exact licence tier held for each of the four paid packs.
- The current Fab revenue threshold.
- That the packaged build contains no loose redistributable source assets.
- That the Steam AI disclosure matches the provenance record.
